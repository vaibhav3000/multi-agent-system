\section{Executive Summary}
This report details the evaluation of a production-grade multi-agent LLM system designed to coordinate specialized sub-agents for complex query resolution. The system is designed to be provider-agnostic, primarily utilizing DeepSeek (via the \texttt{LLM\_PROVIDER} environment variable), while maintaining full compatibility with Anthropic, Groq, Gemini, and a Mock provider for rapid testing. 

The architecture features exactly 7 distinct agents: Orchestrator, Decomposition, Retrieval, Critique, Synthesis, Compression, and Meta. These agents are supported by 4 strictly contracted tools: Web Search, Code Executor, Data Lookup, and Self-Reflection. The evaluation pipeline is comprehensive, encompassing 15 test cases evaluated across 6 dimensions. The entire system is fully containerized and boots end-to-end with a single \texttt{docker compose up} command. 

The source code resides at \url{https://github.com/vaibhav3000/multi-agent-system.git}. The repository contains a total of 36 Python files, comprising 2,240 lines of code.

\section{System Architecture}

The system architecture facilitates asynchronous, decoupled agent interaction through a centralized shared state. The FastAPI application handles incoming user queries and delegates processing to a Celery worker, which updates the \texttt{SharedContext}. 

\begin{verbatim}
          User Query
               |
         [ FastAPI (8000) ] 
          /           \
     SSE Stream     Celery Worker (async)
          \           /
        [ Orchestrator ] 
        /     |     \     \
   Decomp. Retrieve Synth. Critique
       \      |      |      /
      [ Shared Context / DB ] 
              |
       [ PostgreSQL ] --- [ Meta Agent (Self-Improving Loop) ]
              |
         [ Tools ] (Web Search, Code Executor, Data Lookup, Reflection)
              |
        [ LLM Provider ] (Deepseek, Groq, Gemini, Mock)
\end{verbatim}

\subsection{SharedContext Schema}
Agents communicate exclusively by reading from and writing to the \texttt{SharedContext}. This ensures total observability, decoupling, and strict budget tracking.
\begin{itemize}
    \item \textbf{job\_id} (str): Unique identifier.
    \item \textbf{original\_query} (str): The user's input.
    \item \textbf{subtasks} (List[SubTask]): Tasks generated by Decomposition.
    \item \textbf{agent\_outputs} (Dict[str, AgentOutput]): Outputs produced by each agent.
    \item \textbf{tool\_call\_log} (List[ToolCall]): Log of all external tool invocations.
    \item \textbf{budget\_states} (Dict[str, BudgetState]): Token consumption tracked per agent.
    \item \textbf{routing\_log} (List[Dict]): Orchestrator decision traces.
    \item \textbf{final\_answer} (Optional[str]): The fully synthesized response.
    \item \textbf{provenance\_map} (Dict[str, str]): Mapping of claims to source chunks.
\end{itemize}

\section{Agent Deep Dive}
\begin{itemize}
    \item \textbf{Orchestrator} (4000 tokens): Routes execution sequence based on query complexity. Inputs pipeline state; outputs routing JSON. Fails gracefully to a default sequential pipeline if the JSON is malformed or budget is exceeded.
    \item \textbf{Decomposition} (3000 tokens): Generates a dependency graph of \texttt{SubTask}s. Exists purely to plan, not execute.
    \item \textbf{Retrieval} (5000 tokens): Executes tools to fulfill subtasks. Runs multi-hop logic.
    \item \textbf{Critique} (4000 tokens): Assesses the draft answer via \texttt{ClaimScore} schemas. Flags contradictory or unsupported claims. 
    \item \textbf{Synthesis} (6000 tokens): Drafts the final response. Resolves flagged claims directly.
    \item \textbf{Compression} (3000 tokens): Shrinks context if \texttt{needs\_compression()} triggers.
    \item \textbf{Meta} (4000 tokens): The offline self-improvement agent evaluating \texttt{EvalRun}s.
\end{itemize}

\section{Tool Calling and Failure Contracts}
Each tool enforces strict failure contracts.
\begin{itemize}
    \item \textbf{web\_search}: \texttt{TOOL\_TIMEOUT}, \texttt{TOOL\_EMPTY}, \texttt{TOOL\_MALFORMED}.
    \item \textbf{code\_executor}: \texttt{TOOL\_TIMEOUT}, \texttt{TOOL\_EMPTY}, \texttt{TOOL\_MALFORMED}, \texttt{TOOL\_ERROR}.
    \item \textbf{data\_lookup}: \texttt{TOOL\_TIMEOUT}, \texttt{TOOL\_EMPTY}, \texttt{TOOL\_SQL\_ERROR}.
    \item \textbf{self\_reflection}: \texttt{TOOL\_TIMEOUT}, \texttt{TOOL\_MALFORMED}.
\end{itemize}
The orchestrator logs tool calls, handling up to two retries if transient errors occur, logging each attempt independently.

\section{Context Budget Management}
The system tracks tokens using the \texttt{tiktoken} \texttt{cl100k\_base} encoding. 
When an agent calls \texttt{consume\_budget()}, the manager calculates the tokens. If adding them exceeds the budget, it logs a \texttt{budget\_violation} to \texttt{execution\_logs}, returns \texttt{False}, and the agent immediately aborts execution. \texttt{needs\_compression} flags context states exceeding 85\% capacity.

\section{Evaluation Pipeline}
The evaluation harness features 15 test cases (5 Baseline, 5 Ambiguous, 5 Adversarial).
Adversarial cases test prompt injection, impossible guarantees, and hallucination bait.
Scoring dimensions:
1. \textbf{Answer Correctness}: Keyword inclusion ratio.
2. \textbf{Citation Accuracy}: Provenance reference validation.
3. \textbf{Contradiction Resolution}: Flagged claim resolution ratio.
4. \textbf{Tool Efficiency}: Penalizes excessive tool usage ($>6$).
5. \textbf{Budget Compliance}: Penalizes recorded budget violations.
6. \textbf{Critique Agreement}: Verifies flagged claims do not survive synthesis.

\section{Self-Improving Prompt Loop}
\begin{enumerate}
    \item Eval run completes and is stored in \texttt{EvalRun}.
    \item \texttt{POST /evals/rerun} triggers Meta-agent.
    \item Meta-agent finds lowest scoring run and identifies the worst dimension.
    \item Meta-agent maps dimension to responsible agent.
    \item DeepSeek generates a rewrite with structured diff.
    \item Rewrite stored in \texttt{PromptRewrite} as \texttt{pending}.
    \item Human calls \texttt{POST /rewrites/\{id\}} to \texttt{approve}.
    \item System commits to \texttt{AgentPrompt}.
    \item \texttt{get\_active\_prompt()} dynamically serves the new prompt on the next run.
    \item Performance delta is stored.
\end{enumerate}

\section{Streaming and Observability}
The API implements SSE streaming, yielding \texttt{agent\_start}, \texttt{tool\_call\_start}, \texttt{context\_budget\_update}, \texttt{tool\_call\_complete}, \texttt{agent\_output\_token}, and \texttt{pipeline\_complete} events. The \texttt{/jobs/\{job\_id\}/trace} endpoint fetches the aggregated context to reconstruct execution history.

\section{Known Limitations and Honest Assessment}
\begin{itemize}
    \item \textbf{Stub Search}: Currently returns hardcoded stub results unless \texttt{SEARCH\_API\_URL} is configured. Production fix: integrate Serper or Tavily.
    \item \textbf{Event-level Streaming}: SSE emits large blocks of agent output instead of granular LLM tokens. Fix: Refactor the LLM client to yield generator tokens.
    \item \textbf{Code Executor Security}: Runs Python natively. Fix: Implement a Firecracker microVM.
\end{itemize}
